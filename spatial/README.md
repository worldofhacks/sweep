# Shared observation contract — #94, first slice

`contracts.py` and `observations.py` define relay-neutral spatial evidence. The
generated examples in `fixtures/observations-v1.json` are the consumer wire
contract. Run `python -m spatial.vectors` to regenerate them. The portable accepted
event JSON Schema is `fixtures/observation-v1.schema.json`, generated by
`python -m spatial.schema`. Stateful and cross-field checks listed in its
description must also run; JSON Schema alone does not validate a live source.
This package does not complete planner, localization, Android, or MCAP migration.
`relay/platform_observations.py` consumes the qualified world-pose subset for map
display and explicit drive-over recording; it is not the full #94 migration.

Every submitted observation has exactly `v`, `type`, `t`, `event_id`, `session`,
`drone_id`, `connection_epoch`, `source_id`, `node_type`, `t_capture`, `frame`,
`confidence`, and a discriminated `payload`. The relay adds exactly `t_ingest`,
`frame_provenance`, and `authority`. A producer cannot supply those reserved
fields. Accepted observations always have `authority: "diagnostic"`; a declared
world frame or high confidence does not authorize motion, clear occupancy, earn
readiness, or update the planner's pose.

`NodeType` has `aircraft` and `ground_vehicle`. A host-configured source binds
one `source_id` to a device-specific adapter or localization principal, its node
type, permitted frames, and payload kinds. Source declarations are limited to 64
per relay and eight frames per source. Device-local frames have one device owner.
Connection epochs scope their origin: reconnecting never silently reuses the old
odometry origin. Frame declarations are not transforms.

`world` is the canonical static frame. `map_enu`, `building`, device-body,
device-odometry, camera-optical, raw lidar-sensor, and legacy frames remain distinct. No implicit
aliases or coordinate conversion exist here. `frame_provenance` records the
declared frame kind, metric units, axis convention, and local device/epoch origin;
`transform_id` is always null in this slice. Qualified registrations and immutable
map/bundle identity belong to #81/#243. DJI coordinate conversion stays inside
the bridge. `Position` provides no geometric arithmetic: a frame ID alone cannot
establish a shared origin across sessions, device epochs, or approved map versions.

Use `lidar_sensor` with `axes: "unqualified_sensor_scan_angles"` for raw scanner
angles before mounting offset and handedness have been measured. It retains the
local device/epoch origin but asserts no robot-forward, left, or +z alignment.
Display it as raw sensor angles and never project it into world coordinates.
Only a calibrated scan may declare `device_body`; source configuration must not
substitute for measured mounting evidence.

All observation times are nonnegative integer milliseconds, bounded by the exact
JavaScript integer ceiling, in the relay's epoch time domain. New producers must
map their capture clock into that domain. `t` is source transport/send time;
`t_capture` is measurement capture time and cannot exceed `t`. The receiver owns
`t_ingest`. Their difference preserves observed capture-to-ingest latency rather
than replacing capture time with arrival time. Host transport freshness/skew
limits still apply. Capture ordering is tracked independently per source and
payload kind within its current epoch, rather than sharing the ACK/telemetry
transport-order cursor. Capture clock qualification remains an external hardware
requirement; acceptance as diagnostic evidence is not verification of that clock.

The two producer payloads in this slice are:

- `pose`: `position` contains its explicit `frame` and bounded `x_m`, `y_m`,
  `z_m` (±1000 m). Its frame must equal the envelope's frame. `yaw_rad` is either
  null (unavailable) or finite within [-π, π]. Positive yaw is counterclockwise
  about +z in the declared frame; camera-optical observations should leave it null.
- `lidar_scan`: angles use integer millidegrees; distance bounds and ranges use
  integer millimetres. `angle_min_mdeg` is in [-180000, 180000], increment is
  positive, and 1–720 samples span at most 360000 millidegrees. Distances lie
  between the declared minimum and maximum, both bounded by 655350 mm. Null is
  an unknown/unobserved return; zero is invalid. In a qualified body frame angles
  increase about +z from +x. In `lidar_sensor` frames they retain the scanner's
  unqualified reported order. No missing return claims free space.

Pose sources are admitted at most 20 Hz and lidar sources at most 5 Hz per source
and payload kind; the accepted serialized envelope is at most 16 KiB. Confidence
is a finite number in [0,1], independent of registration or safety authority.
Consumers must retain accepted canonical observations with their full bounded
payload. The map-consumption service stores diagnostic envelopes and their separate
host registration bindings in SQLite. It does not add general observation fan-out
to the relay WebSocket protocol.

The named legacy-aircraft compatibility type represents relay-only
`legacy_aircraft_telemetry` observations with an explicitly unqualified legacy
frame, `confidence: 0`, `t_capture: null`, and
`capture_time_available: false`. Original Telemetry v1 `t` remains send time.
No capture timestamp or world alignment is invented. Unsupported legacy values
remain in the original telemetry audit and are not coerced into the narrower
spatial contract. New producers cannot submit the legacy payload kind. The map
service does not enable this compatibility path or promote legacy telemetry into
world positions.

## Qualified map consumption

`WorldObservationService.from_env` reads `SWEEP_WORLD_OBSERVATION_SOURCES`. Blank
configuration disables both live positions and drive-over recording. The exact
JSON object has two fields, `sources` and `registrations`, with identical source-ID
keys. Each source uses the `ObservationSource` declaration described above; map
consumption requires exactly the canonical `world` frame and the `pose` payload.
Each registration contains exactly:

- `reference`: the approved map's `bundleId`, `revision`, and SHA-256 `contentHash`.
- `mapVersion`, `floorId`, `sourceFrame`, and `transformId`: the exact approved
  bundle manifest and measured registration identifiers.
- `qualifiedWorldPose: true`: the host's explicit qualification of this source's
  already-transformed world output. A browser or observation producer cannot set
  this declaration. Saving or approving a map does not establish it.

Deployment must bind each source to an independent configured adapter or
localization credential and the configured device class. No shared-token fallback
qualifies a device identity. Missing frame transforms, clock qualification, and
source measurements remain deployment prerequisites; this service computes none.

Accepted source timestamps and capture times must advance independently. Poses are
limited to 20 Hz per source and epoch. A position expires after one second; its
device must have a current class/epoch and a report no older than five seconds.
Connect the service's `observe_state` hook to authoritative relay state publication
so disconnects, class changes, and new epochs retire previous device origins even
between HTTP requests. A retired epoch cannot become current again.

Recording requires exactly one selected ground robot. The receipt gets a new
observation reference; its durable audit retains the full original pose, tag ID,
authenticated actor, selection, epoch, approved map reference, and host transform
binding. It records the operator's drive-over association and does not assert that
a tag detector observed the tag or that a flight marker is verified. Freshness and
registration are rechecked before the capture is committed. Restarting the service
preserves audit receipts and replay cursors but never restores an old live pose.

The service bounds each session to 100,000 accepted observations and 20,000 capture
receipts, with at most 256 sessions per store. A full or unavailable audit store
refuses further ingestion/recording; it does not silently discard evidence.
