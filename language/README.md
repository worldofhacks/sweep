# language

Capability areas: Interaction and Platform. Milestones: M1 (speech capture, relay-side Whisper transcription, one pinned compiler), M4 (resolvers, full eval, local fallback).

Any engineer may claim a ready task and owns it through review, integration, and evidence. Changes to the plan schema, `validate_plan`, or ordered emission name one change owner and require cross-review.

Plan compiler: swarm state plus intent schema plus final transcript in, an ordered plan of intents out through schema-constrained output. `validate_plan` runs, the console previews, the operator confirms, and intents are emitted one at a time through the relay. Selection and location resolvers, prompts, and a local-model fallback live here. Safety rules live in the arbiter, not in the prompt.

`TranscriptCompiler` sends Claude Sonnet 5 (`claude-sonnet-5`) the `intent-v1-compiler-8` instruction, the operator transcript, and an allowlisted projection of one authoritative relay state event. Its tool schema bounds typed reasons to the compiler enum and permits bounded explanatory detail on plans. Instructions describe intent argument fields, fleet versus selected targets, movement units, and typed-outcome precedence. Unknown aircraft IDs refuse; unresolved room references clarify before camera capability checks; unresolved aircraft descriptions clarify, while unavailable room-navigation resolution remains unsupported. An available alternative capture pattern requires clarification and a new explicit request. The schema exposes every Intent v1 name, while capability and grounding checks decide which names can produce plans in the current state. The projection binds the preview to that event's session, roster, selection, capabilities, and fleet facts. Deterministic validation folds selection, armed state, and aircraft flight states across an ordered plan. It rejects malformed output, unavailable drone IDs, unknown rooms, incompatible flight sequences, and unsupported Intent v1 names before a plan can be previewed. Each step is checked again against the actual terminal state before emission. Provider failures return typed template refusals. Invalid provider output keeps its real response provenance but produces no executable proposal.

Translation remains the frozen Intent v1 `{dx,dy}` contract. `PlanningConfig` derives one translation-grounding value from the authoritative fleet snapshot; the compiler uses that value for language grounding, and confirmation requires the same planner policy before emission. The planner alone applies its configured frame and metres per step. Aircraft-relative language is refused when the snapshot lacks headings for any selected aircraft; Telemetry v1 is not widened to require heading.

The compiler instruction converts metres and feet into configured steps. A directional request with no distance means one foot, or 0.3048 metres. The fail-closed demo grammar grounds `fly`, `move`, and `go` with forward/backward/left/right, explicit steps, feet, or metres; a phrase containing those verb and direction tokens is refused if the whole phrase cannot be resolved. Translation previews show the selected aircraft, resolved physical distance, frame, and each aircraft's world-space direction from the prepared planner result.

Relative altitude language preserves the frozen Intent v1 `altitude {delta}` contract. The compiler accepts bounded `fly`, `move`, or `go` up/down phrases, converts feet or metres with the deployment's trusted altitude step, and defaults an omitted distance to exactly one foot. The same effective immutable capability profile and full altitude grounding are bound into compilation, preview, confirmation, and persisted audit evidence. Absolute `hover at` requests are not representable and produce no plan; plain `hover` remains HOLD. Successful confirmation requires the issued GOTO/HOVER planner result, unchanged grounding and profile, fresh post-dispatch telemetry, the configured three-dimensional target tolerance, and authoritative hovering state. This is synthetic compiler-to-simulator evidence, not live speech or hardware qualification.

`ConfirmedPlan` expires a preview after 30 seconds by default and revalidates its authoritative session, state, and capabilities before each operator-confirmed emission. Relay `accepted` admission and autonomy `executing` events leave the step pending. Only the overall autonomy terminal outcome advances or closes the plan; command-scoped adapter facts cannot do either. Each emission is audited before the relay send. An exception after that point closes the live plan because delivery is ambiguous, preventing a second motion command under a fresh ID. The confirming console remains the registered relay source. The language model never produces timestamps, intent IDs, capture IDs, source identity, confirmation state, or adapter commands.

Synchronous or async motion completion can arrive before relay telemetry. The confirmation retains that terminal event while waiting for telemetry newer than dispatch and at least as recent as the completion event. HOLD and selected LAND require telemetry strictly newer than completion because equal millisecond timestamps cannot prove arrival order. The next `prepare_next()` reconciles it against the current relay state before preparing another step; an explicit `acknowledge()` with fresh state can also finish the final step. Fresh contradictory evidence closes the plan. Before dispatch, the router checks that expanding the intent against current relay state still produces the previewed plan; changed targets require a new preview.

The public router permits one command-bearing execution per relay session. A conflicting motion within the configured window invalidates the active execution, refuses the new intent, and requests a fleet HOLD. Other command-bearing intents and selection changes wait for the active execution to finish. LAND and LAND_ALL retain session-wide ownership from initial dispatch until newer authoritative telemetry proves every remaining target landed. A targeted HOLD removes its covered aircraft from that requirement. If it covers a waiting or unissued landing command, the router cancels the remaining dispatch and retains ownership of uncovered aircraft already landing. Later acknowledgements cannot restart the cancelled commands or restore covered targets. Async landing uses the latest authenticated adapter completion timestamp across the targets, including permitted future clock skew. Failed landing starts a registered safety HOLD before new motion can proceed, including late failed or invalidated ACKs after suffix cancellation. When a partial HOLD completes, the public accepted-plan projection returns to the retained landing owner. Terminal recovery failures block further motion without appearing as executing plans; after execution ends, public SELECT remains available to target a recovery HOLD. Fresh epoch-matched landed telemetry counts toward safe recovery coverage. A pre-dispatch recovery refusal never becomes an execution owner; interrupted motion remains blocked until a successful stop. Successful HOLD and E-stop retire prior executions, so late acknowledgements cannot restart their remaining commands. Resume retains its execution until relay lifecycle publication succeeds; unavailable safety enrichment cancels remaining dispatch with a terminal outcome.

`language/relay_compiler.py` binds the compiler to the relay's voice endpoint. `RelayTranscriptCompiler` implements the `TranscriptCompiler` protocol `relay.voice.TranscriptService` calls after Whisper returns: it resolves the relay session by ID, grounds one `TranscriptCompiler` per session on that session's log through `SessionCompilerAudit`, passes the planner's translation policy and the composition's capability profile (which must equal the profile the relay state advertises), never qualifies voice estop, and renders the typed outcome as a `relay.voice.VoicePlan` preview: ordered Intent v1 drafts with the arbiter's confirmation requirement and deterministic per-step grounding notes for a plan, the authoritative rooms or selectable aircraft as options for a clarification, or the typed reason for a refusal. A `model_unavailable` refusal is reported to the endpoint as `compiler_unavailable` so the console falls back to its labelled local matcher. Aircraft-relative motion needs per-aircraft headings the relay state does not carry yet, so it is refused rather than guessed. The console emits each step only after the operator confirms it in the dock, and the relay re-validates it like any button press. `relay/tests/test_voice_plan.py` runs the reviewed corpus's `live_demo` cases through this path with a replay cassette.

Compiler and confirmation construction requires an audit sink. Production uses `SessionCompilerAudit` with the relay's append-only session log; tests can use `InMemoryAuditSink`. A compiled-plan record contains the full validated grounding projection, ordered immutable intents, expiry, model and prompt versions, response provenance, and a digest over those fields. `CompiledPlan.from_audit_event` revalidates that record before restoring an executable preview. Records exclude the transcript and provider credentials.

Model telemetry uses a lazy Langfuse client when its public and secret keys are present. Keyless runs use a no-op sink without network calls or warnings. Traces group on opaque correlation and authoritative session IDs. They record model and prompt versions, direct or replayed response source, original response source, cassette digest, usage, latency, and a grounded score. Tracing failures cannot interrupt compilation.

The CI corpus loader pins the reviewed 50-case `datasets/utterances/transcript_plan_cases.jsonl` release and retains the initial JSON corpus as a compatibility fixture. Synthetic responses exercise the pipeline while reviewed provider recordings are assembled. New replay cassettes bind `claude-sonnet-5`, `intent-v1-compiler-8`, one immutable byte digest, and the recorded origin label; prior provider artifacts remain immutable evidence for their recorded prompt versions. Replay output reports `unverified_replay` because an editable cassette cannot authenticate that label. A replay never falls through to a live request.
